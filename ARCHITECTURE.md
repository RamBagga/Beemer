# BEEMER — High-level architecture

Beemer is a single-machine, batch-updated research app: a **Python data pipeline** pulls free public market data
into **local storage** once or twice a day, an **analytics layer** turns it into per-company metrics and a
**Buffett Score**, and a UI presents it to beginners.

Two UIs read that same data. **Streamlit** (`app/`, deployed from `main` as `app/main.py`) is the legacy app and stays in place. **Spring Boot + React** (`backend/`, `frontend/`) is the new stack: the API reads SQLite only, and the React app reproduces the Studio/Night design system. The pipeline still owns ETL.

## Components

| # | Layer | Code | Responsibility |
|---|---|---|---|
| ① | **Data sources** | — | Yahoo Finance (prices from 1996 for the oldest names, indices `^NSEI`, `^BSESN`, `^CNXIT`), NSE archive CSVs (index lists for `--universe nifty50/100/500`), screener.in public pages (P&L, balance sheet, cash flow, ratios). Universe is the curated `data/universe_tech.csv`. |
| ② | **Ingestion** | `update_data.py` | Idempotent, incremental. Prices: re-fetch last 10 days and upsert; if adjusted closes shift on the overlap (split/dividend), reload that symbol's full history. Fundamentals: refreshed when > 7 days old, politely rate-limited, raw HTML cached. Ends by calling `analytics.build_metrics()`. Modes: default (EOD), `--prices-only` (snapshot), `--full-prices`, `--force-fund`, `--universe`. |
| ③ | **Storage** | `data/` | `market.db` (SQLite) is the system of record: `prices`, `universe`, `fundamentals` (long format: symbol/section/item/period/value), `fund_meta`, `runs`. `metrics.parquet` is the pre-computed, denormalised table the UI reads (fast screener). `screener_cache/` holds raw pages so parsing can be re-run offline. All three are regenerated by the pipeline and are git-ignored. |
| ④ | **Analytics** | `analytics.py` | Pure functions over pandas: price cleaning, returns/CAGR, drawdowns & crash/recovery episodes, SIP vs lump-sum (XIRR), fundamentals metrics (ROE/ROCE consistency, debt, growth, margin stability as a moat proxy, FCF conversion, P/E vs own 10-yr median, simple DCF-style intrinsic value), and the 0–100 **Buffett Score** (ROE 20 · debt 15 · growth 20 · moat 15 · cash 15 · valuation 15, rescaled when data is missing). |
| ⑤ | **Presentation** | `app/` | Streamlit multipage app. `beemer.py` is the shared design system (CSS, Plotly template, colours, KPI/badge/gauge components, plain-English explanations, data loaders cached 10 min). Views: **Cockpit** (market overview, sub-sectors, IPO tracker, rolling returns, crashes, SIP sim), **Screener** (ranked + filters + quality-vs-price map), **Company** (verdict, checklist, financial history, valuation), **Academy** (lessons, glossary). Theme in `.streamlit/config.toml` at the repo root (always run `streamlit run app/main.py` from the root); brand assets in `app/static/` and `design/`. |
| ⑥ | **Scheduler** | `scripts/` | `install_cron.sh` writes two weekday cron lines (converted from IST to the machine clock); `run_update.sh` runs the pipeline with a lock so runs never overlap. Optional — `./start.sh --cron`. |
| — | **Launcher** | `start.sh` | Creates `.venv` (prefers Python 3.12), installs deps, bootstraps data if missing, starts Streamlit in the background on 8501 (or the next free port), health-checks it. `--fg`, `--stop`, `--status`, `--cron`. |

## Data flow (one daily cycle)

1. **15:45 IST** — cron → `run_update.sh snapshot` → `update_data.py --prices-only`: latest prices upserted → metrics rebuilt.
2. **18:30 IST** — cron → `run_update.sh eod`: prices again (final close) + fundamentals for any company whose data is > 7 days old → metrics rebuilt.
3. `build_metrics()` reads SQLite, cleans prices, computes metrics + score for each company, writes `metrics.parquet`.
4. The running app picks up new data within 10 minutes (Streamlit cache TTL) — no restart needed.
5. Company pages read full price/fundamental history straight from SQLite on demand.

## Deployment topology

Locally, cron on the Mac runs the pipeline against `data/market.db`. In the cloud, the same pipeline runs in **GitHub Actions** (`update-data.yml`, weekdays 15:45 and 18:30 IST) and publishes `market.db.gz`, `metrics.parquet` and `manifest.json` to the rolling GitHub Release `data-latest`. Hosted apps (Streamlit Community Cloud, Render, Docker) never build data. `bootstrap.py` downloads the snapshot when it's missing, checks for a newer one every 6 hours, and swaps it in atomically, and the app then clears its caches. Details and free-host comparison: [DEPLOYMENT.md](DEPLOYMENT.md).

## Spring Boot + React

```mermaid
flowchart LR
    ETL["update_data.py<br/>analytics.py · picks.py"] --> DB[("market.db<br/>prices · fundamentals<br/>company_metrics · picks")]
    ETL --> PQ["metrics.parquet"]
    PQ -->|import if the table is empty| DB
    DB --> API["Spring Boot 3 · Java 21<br/>/api/cockpit · /screener · /companies · /picks · /sip-simulator"]
    API --> WEB["React · Vite<br/>Cockpit · Screener · Company · Academy"]
```

`update_data.py` writes `company_metrics` (one JSON payload per symbol) next to the parquet file. `bootstrap.py` backfills that table when a published snapshot has parquet but no table yet. Request-time maths (CAGR, drawdowns, crashes, SIP/XIRR, rolling returns, price cleaning, screener filters, P/E vs history, fundamental charts) live in `backend/src/main/java/com/beemer/math` and are checked against Python golden files in `backend/src/test/resources/golden`.

The API caches cockpit, company, screener and price series for 10 minutes (Caffeine). On startup, if `data/market.db` is missing, it downloads the `data-latest` GitHub release the same way `bootstrap.py` does. Swagger is at `/swagger-ui.html`. Health is `/actuator/health`.

## Swapping in licensed data later

Free sources (Yahoo, NSE website, screener.in) are licensed for personal / non-commercial use only. To sell Beemer:

- **The seam is the storage schema.** The UI and analytics only read `market.db` + `metrics.parquet`; they never call a source. A new provider just has to fill the same tables:
  - `prices(symbol, date, open, high, low, close, adj_close, volume)` — from an NSE/BSE data licence or a vendor (CMOTS, Accord Fintech, ACE Equity, etc.).
  - `fundamentals(symbol, section, item, period, value)` — sections/items mirror screener's P&L / balance-sheet / cash-flow rows; map vendor fields or parsed XBRL filings onto them.
- **How:** replace `update_prices()` / `update_fundamentals()` in `update_data.py` with provider modules (e.g. `providers/cmots.py`), keep `_store_prices()` and the upsert logic, then call `build_metrics()` as now. Keys go in `.env` (already git-ignored).
- **Scale-out path:** SQLite → Postgres when there are multiple app instances; the parquet metrics table can move to a DB table or object storage; cron → a managed scheduler (GitHub Actions, Cloud Scheduler) running the same `update_data.py`.
- **Compliance:** keep scores framed as education; review SEBI Research Analyst / Investment Adviser rules before showing buy/sell-like signals to paying users.
